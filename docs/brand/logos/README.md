## 0. 三套方向一句话

| | 方向 | 物种 | 概念 | 主用途 |
|---|---|---|---|---|
| **A** | 证印 / Open Seal | 线 · 符号领先 | 右上开口的方印 + 指向开口的验证笔 | 母品牌主标志 |
| **B** | 开字 / Open-Counter | 字 · 字标即符号 | 没有图形符号，两个大写 P 的字腔各开一道口 | Protocol / 文档 / 开发者侧 |
| **C** | 双面 / Private & Public | 块 · 图块领先 | 一枚证卡：上段实心=牌面私密，下段明线=结果可验 | 应用图块 / 产品与活动物料 |

**推荐：A 为母品牌主标志，B 降级为协议与开发者侧的次级锁定式，C 不进母品牌、转给扑克产品图标或发布活动物料。**
理由：A 直接落在策略文档 §6.1 已授权的"开放证印"概念上，且在 16px、单色、正负形三种约束下最稳；
B 的概念最干净但缺少独立图符；C 的语义需要一句解释才读得懂，离"可验证"的字面联系最远。

## 1. 三套共用的系统规则

这些规则是这次探索真正的产出，选定方向后不要丢：

1. **开口一律落在 1:30**（右上角弧的中点）。A 的方印缺口、B 的 P 字腔开口同方向，
   这是"游戏不是黑箱"的固定手势，也是动效锚点：每局验证完成时开口闭合 120–180ms（§6.5）。
2. **方印视觉高度 = 字标大写高**（102.4 : 100），二者共用同一基线；图符与字标间距 30 单位。
3. **绿色只表示验证**（#18A66A 夜场 / #0E7A4E 纸白）。金色 #D4A72C 属于资金与结算，
   因此**不进入标志**——历史草案 `proofplay-logo.svg` 里的金色菱形与此冲突，已不沿用。
4. **单色必须成立**：所有 `*-mono.svg` 用 `currentColor`，随上下文取色，不含第二颜色。
5. **字标是路径，不是字体**。历史草案用 `<text font-family="-apple-system">`，换机器就变形，
   不是可用 logo；这里 9 个字形（P r o o f P l a y）全部按几何骨架绘制：
   大写高 100、x-height 70、降部 128、monoline 等宽描边、butt 端点。
   A/C 用 w13 + 圆字腔 + 字距 10；B 用 w15 + 方字腔 + 字距 7.5。
6. **五不原则**（§6.2）：不用 Z、不用链环、不用扑克牌外形与花色、不用盾牌、不用渐变发光。

## 2. 各方向要点

### A 证印 / Open Seal
- 含义映射：方印=凭证与承诺；右上开口=不是黑箱；验证笔指向开口=证据把它闭合。
- 强：16px 起即成立，可直接当 favicon；B2C 与 B2B 通吃；动效天然。
- 弱：与通用 verified 徽章同族，识别独占性得靠字标扛；符号偏理性，游戏张力三套里最弱。
- 待办：A 的开口在 16px 下与验证笔开始粘连，若要长期当 favicon，建议再加一档
  "16px 简化版"（只留开口方印，去掉验证笔）。

### B 开字 / Open-Counter
- 含义映射：字标即符号，两个大写 P 的字腔各开一道口 = 不做黑箱；含义只有一种读法。
- 强：一个资产走天下，不必维护符号与字标的对齐关系；协议与开发者侧气质最正。
- 弱：没有独立图符，app 图标只能截取"开口的 o"，而它在小尺寸下更像 G/C；普通玩家侧温度最低。
- 实测结论（重要）：**开口不能落在 o / a 上**。试过把开口铺到所有字腔，
  o 会被读成 u 或 c，"Proof" 读成 "Prucf"，因此开口只保留在两个大写 P 上，
  作为签名而不是花纹。图符用的开口的 o 是单独构造的。

### C 双面 / Private & Public
- 含义映射：直接编码 §6.4 的 Secret/Public 双层——实心段是玩家看不见的牌面，
  明线是任何人都能复验的记录。
- 强：三套里唯一用正形（实心）的方向，图块感最强，最像游戏产品。
- 弱：语义需要一句解释；下沿明线在 16px 退化；与"可验证"的字面联系最远。
- 实测结论：**左右对半分会被读成字母 B/D**，因此改成上下分段。

## 4. 第二路：纯图形方向（`out/pic-d` … `pic-i`）

第一路被评价为"一个单词加一个复选框"——它确实是通用 verified 徽章的形。第二路**不继承**第一路的
方印、括号、对勾，只继承设计理念。

**母品牌不绑定扑克**：牌、花色、牌桌、筹码全部撤掉，只留任何游戏都成立的事。

| | 方向 | 图形 | 寓意 | 判读 |
|---|---|---|---|---|
| **A** | 开盖 / Open Box | 敞口的箱（粗壁 U 形），盖被整个掀起，箱里那一条是绿的 | 不要求你相信：盖子是开的 | 一眼读得出"打开的箱子"；16px 靠"盖 + 盒"两个体块撑住 |
| **B** | **两半 / Split Round** | 一个圆被一刀切成两半，沿切口滑开，一半是绿的 | 任何一方单独握着都不是一局 | **推荐之一**。最简、最稳、单色与 16px 全过；圆＝一局，正好挂住"明局" |
| **C** | 刻痕 / Tally | 三道计数刻痕，被一道绿色斜线划上 | 最古老的"有账可查"：这一局被记下来了 | 读得出"划了账"；但 16px 下三道竖痕会并成条纹，已备两道竖痕的简化版 |
| **D** | 标尺 / The Ruler | 一把带刻度的尺斜着压下来，绿色那格正在被量 | 把尺子交给玩家：每一局你自己量 | 读得出"尺 + 测量"，刻度是关键特征；小尺寸下刻度退化为梳齿，仍成立 |
| **E** | 跷跷板 / Seesaw | 杠杆支在中间，两端各坐一方，绿的那端这局高 | 博弈有输赢，但支点在哪里看得见 | 读得出"杠杆 + 两方"；动感六套里最强，但离"可验证"字面最远 |
| **F** | **手柄 / Gamepad P** | 极简游戏手柄（胶囊机身 + 十字键 + 绿色确认键），顶部引出的线向上绕成字母 P | P 不是贴上去的字母：Play 与 Proof 是一条线 | **推荐之一**。唯一同时给出"游戏"与"P"的方向；手柄天生品类中立；app 图块最像游戏产品 |

**推荐在 B 与 F 之间定**：B 胜在极简与单色稳健、且挂得住"明局"；F 胜在一眼就是游戏、
自带首字母 P，识别独占性最强，代价是比 B 多一层细节（16px 用简化版去掉十字键）。
字标仍用第一路的定制几何骨架（`pic_lockup` 已排好，图符视觉高 = 字标大写高，同一套基线规则）。
A 适合做"验证入口 / Proof 产品"的动作图标，C 适合做局记录与账本类界面，D 适合数据与审计页。

### 这一路推翻过的（别再重试）

**因为"读不出是什么"被推翻：**

| 试过的 | 实际读成 |
|---|---|
| 落子（十字 + 一子，子压在正中心） | 靶心 / 加号按钮 |
| 开箱（角上凿一块 + 取出的块） | 拼图 / 二维码定位角 |
| 切牌（两叠等分横块） | 两根横条 / 暂停键 |
| 发牌（牌堆 + 飞出的小牌） | 两个不相干的色块 |
| 开盖第一版（实心方块 + 上方一条杠） | 保险箱 / 公文包，完全没有"打开"的意思 |
| 照 / Spotlight（两条斜光 + 地平线） | 字母 A / 帐篷 |

**因为"绑死扑克"被推翻**（它们其实读得出来，但母品牌不能是牌）：
牌背（斜带圆角矩形）、摊牌（两张牌摊成 V）、双牌（两张错叠，还额外读成"复制"图标）、
掀角（折角方块，读成文档图标）、抽牌（牌堆 + 一张牌）。

### 两轮里沉淀出的两条硬规律

1. **极简不能靠删识别特征。** 把物件删到只剩圆角矩形，它就不再是那个物件。
   要么保留一个决定性特征（箱子的敞口、圆的切口、刻痕的斜划），要么就别用这个隐喻。
2. **对称会杀死隐喻。** 子压在网格正中就读成靶心，圆环加一段弧就读成进度条。
   偏置（两半沿斜切口滑开、斜线压在竖痕一侧）才是"物件"，居中是"符号"。

## 5. 未达项与需要你拍板


1. **`明局` 中文字标仍是系统黑体占位**（`<text>` + PingFang），不是定制字形。
   中英副排要能投产，`明局` 两字得单独设计，且"明"的日/月结构与 A 的方印有天然呼应，值得做。
2. **旧 `docs/brand/proofplay-logo.svg` / `-mono.svg` 没有替换。**
   它们与本文件在同一目录并存，是否废弃、以及是否把 A 提升为正式主标志，等你定名结论后一并处理。
3. **A 与通用 verified 徽章同族**是策略风险，不是几何问题。建议按 §10 的指标做一轮
   8–12 名玩家的 5 秒测试，把 A/B/C 三张主锁定式一起丢进去，用结果而不是口味来定。
4. **定名前不投产**：商标（中国 9/41/42 类、美/欧/英）、域名、应用商店与母语语义清查
   未完成前，这些都是内部原型资产。
5. 字标的 `y` 左臂与右臂交接处有 monoline 固有的小台阶，`f` 的钩偏保守。
   若要做正式投产版，这两个字形值得手工修到光学平衡（参数化骨架下是局部改动，不影响其他字形）。
